# Guides

![Five staggered numbered cards for review, design, spec, and system work connected by a dashed path](/images/heroes/guides-index.png){.page-hero}

Use these guides by job. You can practice the method manually, study the examples, or go deeper into the NDD vocabulary.

## Understand the method

Start here if you are new to NDD.

- [What is NDD?](/what-is-ndd): the problem, the taxonomy, and the basic hierarchy.
- [Anatomy of a Product Model](/explanation/anatomy-of-a-product-model): the concrete shape of the model NDD creates.
- [What Makes a Narrative Buildable?](/what-makes-a-narrative-buildable): the checklist for whether the model is clear enough to build from.
- [How it Works](/how-it-works): the prompt-to-model-to-review loop.

## Use NDD without Auto

Use this path when you want to prove the method with tools you already have.

- [Using NDD without Auto](/using-ndd-without-auto.html): one copyable narrative, one behavior slice.
- [Prompting AI with NDD Vocabulary](/guides/prompting-ai): how to use the taxonomy in prompts.
- [Review a Narrative](/guides/review-a-narrative): a checklist for catching missing outcomes, vague rules, and unexplained data before build.

## Study the example

Use this path when you want proof on product-sized examples.

- [Your First Narrative](/guides/first-narrative): a smaller entry point into the same concert-booking domain.
- [Build the Concert Booking Platform](/guides/build-concert-platform): the beginner canonical example with capacity, waitlists, outcome scenes, and all four moment types.
- [Model the Lens Rental Marketplace](/guides/lens-rental-marketplace): the serious example with trust, payments, access control, workflow reversal, handover evidence, and dispute resolution.
- [Structuring Domains, Narratives, and Scenes](/guides/structuring-narratives): how to decide what belongs at each level.

## Go deeper

When the basics are clear, the explanation and reference sections cover the method in more detail.

- [Reference](/reference/): vocabulary, moment types, rules, examples, and should statements.
- [Explanation](/explanation/): data completeness, cohesion, review views, progressive control, and lineage.
